- **Changed: the Git Bash CI job runs in shards behind one check (#1197).** For contributors: `.github/workflows/gitbash.yml` now splits the `gitbash`-tagged test files across Windows shard jobs, balanced by the per-file times in `scripts/ci/gitbash-times.txt`, sized so each shard fits its 30-minute limit again. The check name is still `Git Bash tagged files`: a gate job reports it, pending from the start of the run and green only when every shard succeeded. A tagged file with no row in the table still runs, weighted 60 s; the table's header says how to refresh it. To retry a red check, re-run failed jobs, not a single shard.
