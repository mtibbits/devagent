- **Changed: commands refuse a held issue (#963).** While an issue's STUCK is
  an operator question (`Kind: question`, written by `hold.sh`), pull, switch,
  resume, revise (with or without `--retier`), unstuck, checklist-unstuck,
  stuck and checklist-stuck change nothing, print the STUCK path and its answer
  line, and exit `operator-question`, the exit `/devagent:next` already uses.
  Pull's trust and quarantine codes still win. stuck and checklist-stuck check
  and write under the issue's question lock when it has a `questions/`
  directory, so a hold in progress is never overwritten. sync leaves the held
  closeout row `[?]`, and reap no longer turns a question STUCK into a
  follow-up chore. Any other STUCK is handled as before. `_toml.py list-keys`
  now exits 2 on a file it cannot load and 3 on a named table that is not a
  table, and `list-tables` exits 2 on a file it cannot load, where both raised
  a traceback.
- **Changed: `--ready` leaves out held, stuck and parked issues; portfolio
  schema 1.4 (#963).** `/devagent:portfolio --ready` no longer offers a leaf
  whose issue has a STUCK file or is parked in devagent's state. The portfolio
  now reads each project's state file (never writing it): the document's
  IssueEntry carries `parked` and `stuck.kind`, a state file that cannot be
  read fails closed (`parked: null`, a `state_unreadable` report entry, and a
  `--ready` stderr line), and version rule 7 lets a minor bump add a
  condition to the ready rule; a reader at another minor takes `ready` as
  written.
