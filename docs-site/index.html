What each step does

Why it's different

  • Requirements first. devAgent's own behaviour is written down as {{count:requirements}} requirements in one file, from business rules down to functional ones, and its tests keep that file in shape. Read them.
  • Fresh eyes before it ships. By default, reviewers started in a fresh context, which never saw the drafting, red-team the merge request and verify the branch against the issue's acceptance criteria. How the checks are dispatched.
  • Shipping on evidence. The test evidence a merge request records is checked against the recorded test-suite run for the exact commit being shipped, not taken on a claim that the tests pass. How evidence is recorded.
  • The record on disk. Every issue keeps a folder of plain files: its checklist, plan, reviews and merge-request body. Any session, today's or next week's, picks it up where the last one stopped. The checklist and its steps.
